# Build status

## Completed

- Existing React 19, TypeScript, Vite, npm lockfile, Geist/Geist Mono, paper/ink CSS tokens, five routes, accessible navigation, community disclaimer, landing page, and guest onboarding preserved. No new dependencies were needed.
- Nine real simulated rounds: SEE ×3, ACT ×3, LAND ×3. Target pacing is roughly 3–5 minutes for decisions and short feedback; deeper event replay is optional and self-paced. There is no forced countdown or measured user-duration claim.
- Pure versioned TypeScript engine at `src/lib/simulation.ts`, with separate contracts (`simulation-types.ts`), authored scenario data (`scenarios.ts`), scoring (`scoring.ts`), and formatting/UI. Default scenario 3.0.0, uint32 seed 42. Same version, seed, and actions reproduce identical outcomes.
- Engine uses illustrative ticks and safe-integer invented credits. No Solana millisecond or real-money interpretation. Decisions consume zero simulation ticks; time does not advance while the player reads, selects a path, or waits.
- Pre-decision projection exposes only the observed executed-event snapshot, signal age, estimates, costs, execution guard, net minimum, expiry, uncertainty flag, and known synthetic schedule. Later market events and realised outcomes are withheld until commitment. No pending-flow access.
- SEE covers a fresh useful observation, a stale observation that travelled while the market changed, and a case supporting Pass. ACT covers positive net estimates, costs erasing benefit, and an unknown later market change. LAND covers an eligible positive inclusion, inclusion/execution without profit, and an Other-produced block with the Raiku example unavailable.
- Raiku co-location example is an explicitly authored path, enabled only for an eligible opportunity arriving before a Raiku-produced target block within its lifetime. UI disables unavailable paths; engine rejects them independently. Other submission is generic and names no competing provider. No forced profit for the Raiku label.
- Complete round ledger: gross benefit, included-attempt network fee, success-only trading costs, trade P&L, separate operating costs, net result, and an uncharged counterfactual for possible forgone opportunity. Dropped transactions pay no network execution fee. Included failures explain their 6-credit simulated fee. Passing has zero trade P&L and actual costs.
- Exact 3 + 4 + 3 category contributions after every round, out of 10; full run out of 90. Scoring accepts only decision-time information, not realised outcomes. Unknown later events cannot reduce an otherwise sensible decision's points. Learning score stays separate from simulated P&L.
- Every round includes explanation and ordered engine event replay, with self-paced event navigation and lightweight display-only CSS fades. The continuation control and exact point contributions are near the outcome summary so optional deeper review does not gate the next decision.
- Results aggregate each mission, costs, and net results; any of the nine rounds can be replayed. Downloadable SVG cards show scenario version, seed, and learning score. No network finality is implied.
- Version/seed-keyed local best records reconstructed from actions, last-run results, and in-progress decision/review resume after reload. Old prototype progress remains retained separately and is never compared with new scores. Reset clears all generations. Blocked/corrupt storage does not prevent guest play.
- Original self-paced beginner Act/Pass tutorial, optional 24-character name, device reset, and click/touch/keyboard glossary preserved. About and glossary now distinguish modeled integer-credit net results from real trading profit and unmodeled finality.
- Requirements updated in `CLAUDE.md`. Exact scenario, accounting, coverage, scoring, and reproducibility rules documented in `docs/SIMULATION_RULES.md`.
- Repository-root Netlify configuration remains unchanged: base `.`, build `npm run build`, publish `dist`, Node 24, non-forced HTTP 200 SPA fallback to `/index.html`. Hosting instructions remain in `docs/DEPLOYMENT.md`.
